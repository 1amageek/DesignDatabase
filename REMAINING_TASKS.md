Updated: 2026-08-11

bootstrap. The following work is required for the complete production path. No task
authorizes a change to `database-framework` or a direct `storage-kit` dependency.

## Cross-Package P0 Dependencies

The following are not DesignDatabase implementation responsibilities, but production use
cannot complete without them:

| Owner | Required task |
|---|---|
| `Xcircuite` | Activate the implemented secret-free multi-database mount manifest through provider profiles, then add exact dependency graph resolution, one-target mutation admission, exact action/artifact selection, and database session lifecycle |
| `DesignFlowKernel` | Candidate review/promotion policy bound to exact base and resolved dependency graph |
| `ReleaseEngine` | Immutable multi-database release bundle and dependency-retention verification |
| `circuit-studio` | UI that distinguishes project, active target, pinned dependencies, candidate, permission, and approval |

## Explicit Non-Tasks

- Modify, patch, fork, or vendor `database-framework`.
- Add a DesignDatabase raw bootstrap/keyspace directly on `storage-kit`.
- Reimplement generic transaction, query planner, index lifecycle, migration, service, or backend.
- Store DesignDatabase pages, indexes, WAL, or recovery state in `.xcircuite`.
- Treat OpenDB/OpenROAD as the canonical backend.
